# 编程会话所有权日志

[English](guide.md) | 中文

## 变更

`coding_session_handoffs` 所有权日志采用第 2 版，以保留重启恢复检查点及未解决的原生准入请求。已有第 1 版日志会阻止启用。前版读取器拒绝第 2 版日志，不会丢弃恢复字段。原生历史及独立的 `coding_sessions` 镜像存储域保持原有格式。

## 迁移

1. 升级前，停止使用所选存储后端的所有 Host。全新后端没有需要转换的日志；首次所有权写入会创建第 2 版。
2. 对于已有 JSON 后端，保留完整的 `coding_session_handoffs.json` 文件及其摘要作为备份。其他后端应保留整个 `coding_session_handoffs` 存储单元。不要删除该单元或创建空日志来绕过拒绝。
3. 已有第 1 版数据需要经过独立审阅的离线转换，保留每个所有权标记及全部已有字段。验证完整来源单元、确切版本、标记身份及字节／数量限制，并在发布前确认输入摘要未变。没有自动转换或受支持的降级；不要盲目修改版本标记。参见[所有权包](../../../../packages/session/coding-session/README.zh.md#known-limitations-and-deferred-work)。
4. 确认转换后的单元可通过当前所有权模式打开，且未丢失标记数量、所有者令牌或未解决准入请求。启动必须拒绝损坏数据或不匹配版本。
5. 回退代码时，保留第 2 版日志。旧读取器必须保持拒绝。产生后续准入请求后恢复升级前的备份会丢失新增不确定状态，不属于受支持的回滚。
