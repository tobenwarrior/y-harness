## 概述

浏览项目和共享技能，查看完整指令与历史，并审阅可复用流程提案。已有技能保持受保护，直到明确接管文件；符合条件的技能通过审阅后的提案进行管理。恢复归档资源包或回滚指令更改时保留历史。此包提供面向人的技能库；模型调用由[技能子系统](../../../docs/subsystems/skills.zh.md)负责。

<a id="inventory-and-protection"></a>
## 清单与保护

技能库复用文件系统发现机制并关闭监听，保留调用注册表通常隐藏的同名候选。已注册 Workspace 路径决定项目根目录。全局注册表与当前已挂载的 Agent 注册表补充受保护的内置及自定义摘要；查询不会挂载未启用的预设。原生提供方只通过现有连接提供元数据，不启动进程。提供方可用性与使用记录覆盖率相互独立。

身份由提供方及规范化的指令位置组成。在归档位置重新创建文件会产生独立的活动身份，保留原归档。已有文件默认受保护；内置和原生条目不能接管或归档。接管只确认当前文件哈希，并保持自动清理关闭。之后的手动编辑会恢复保护，直到再次明确接管。固定条目不参与维护。

常规清单、`retrieve` 和详情读取使用根文件，并复用与准确根哈希匹配的逻辑引用目标缓存；它们不打开生成主题或来源片段。缓存不确认子文件当前是否完整。生成根文件没有匹配缓存时，会报告引用不完整，直到明确选择接管、验证其资源并记录引用目标。选定的学习、接管、清理和修订操作会在使用前验证生成资源。 链接识别忽略 Frontmatter、代码、自动链接及普通链接标题，包括目标路径含转义标点后的标题。

仅当成功的 Harness `skill` 工具结果与一个本地文件的提供方、名称、资源目录及当前指令文本唯一匹配时，才记录加载。加载次数不表示任务成功。显式指令注入、历史会话与原生隐式加载的覆盖率未知；零次记录不表示未使用。系统不按闲置时间淘汰技能。

<a id="maintenance-and-history"></a>
## 维护与历史

清理预览包含完整的修改前后根指令，以及所有拟生成的主题文件、来源回执和入口回执。受管理且未固定的文件可移除围栏代码之外过多的空行。位于自有目录中的过大 `SKILL.md` 入口还可以将完整章节移到链接的主题文件，同时保留准确来源。拆分预览说明根指令减少的大小及内容保留情况，不表示总存储空间减少。可配置正文预算只标记需要语义审阅的条目，不截断指令。

<a id="managed-markdown-limits"></a>
### 受管理 Markdown 的限制

每次新建受管理技能、编辑指令、清理和回滚时，都会检查每个完整输出文件是否同时满足知识库的两项上限：最多 200 个屏幕行，以及 25 KiB 的 UTF-8 字节。屏幕行计量与知识库按宽度 90 使用 Python 换行的约定一致，包括短行不换行的行为；它不是物理行数，也不是编辑器中的像素宽度。Frontmatter、空行、导航和来源回执均计入限制。计量不会重新排版来源。接管仍是明确且不写入内容的例外：它可以授权审阅现有过大文件的清理，而不改写受保护文本。

安全拆分保留根文件的 Frontmatter、标题和介绍，以及标题锚点。移动后的链接会重新定位；可读主题、准确的原始来源片段和计划中的根文件回执存储在 `.y-topics` 下不可变的生成版本中。每个生成版本最多包含 64 个内容文件，其中包括最多 31 个可读主题、对应来源片段、开头的来源片段和 `entry.txt`；经过检查的清单属于单独的元数据。普通技能加载首先读取有上限的根文件，仅在需要时读取链接的主题。

自动拆分要求来源是未固定、明确加入管理的普通根文件 `SKILL.md`，并位于其自有资源包中。此策略不改写受保护、供应方、原生、其他所有者、链接或独立 Markdown 来源。不受支持或含糊的 Markdown 和链接、不可分割的过大块，以及无法容纳的索引，都会返回明确的处理提示，不生成部分拆分结果。保留简短的根入口及人工链接的主题文件，然后重新审阅；不要截断指令来满足上限。

新建技能会先在发现范围之外暂存并验证完整且符合上限的根文件与生成子文件，再发布资源包。编辑会先发布经过验证的子文件，再通过已有修订日志替换根文件。每个入口最多保留八个生成版本；第九个会被拒绝，不会清除旧版本。未改变且属于当前所有者的中断暂存可以继续；已改变或其他所有者的资源需要人工恢复。已有技能维护检查负责这些操作；其他知识库 Markdown 文件和 Memory 采集不属于此包的职责。

应用预览前检查来源哈希并保存上一版。文件替换与管理状态提交具有恢复日志。后续冲突编辑会保留，上一版仍可恢复。回滚会验证选中的历史替换内容，并按相同的完整文件上限接纳它：安全拆分过大的旧指令，或拒绝不可分割内容和独立文件。它记录新修订并保留旧资源。完整且确定的历史生成版本可以重用，无需读取已损坏的当前生成版本；已改变的历史资源不会重新生成或覆盖。明确归档会将整个资源包移动到同一文件系统的嵌套 `.skill-library-archive` 目录，以供恢复，其中包括需要人工检查的生成资源。恢复以独占方式创建目标，并保留归档副本，不覆盖已占用位置。中断恢复会保留两处内容并报告恢复警告。

自动空白清理需要接管后单独为技能启用。轮询间隔默认十分钟，设为零可禁用。已有用户、供应方及未知所有者技能不会自动接管或编辑。服务不提供永久删除端点。

<a id="evidence-and-semantic-proposals"></a>
## 证据与语义提案

Host 捕获的观察记录不可变地保留任务、会话和事件身份。符合条件且已完成的实质性实时 API 任务可以自动生成创建或更新提案；完成状态、工具成功交付和进程输出不代表技能使用成功。提供方接收有预算限制的元数据、选定的完整正文和观察记录。对于选定的生成入口，语义检查会验证完整生成版本，从连续回执中重建唯一的准确原始来源，检查其 SHA256 和计划中的根文件，并重新计算拆分，然后使用已有提案及验证流程。资源缺失、改变、伪造或含糊时拒绝操作。已有输入预算及资源文件数量和字节预算仍适用于完整来源与资源包；超限会明确拒绝，不截断内容，也不进行部分验证。`learn` 在提出更新前选择相关的受管理来源，并拒绝压缩或归档草案；新建会先检查已有元数据，将审阅后的目标位置绑定到当前已注册项目路径，并选择项目中的新位置 `.dsh/skills/<name>/SKILL.md`。未知字段、任意截断和未选定来源的写入会被拒绝。

语义修订保留元数据和分隔符已有的换行，在替换正文前补上缺失的换行，并在写入来源或历史记录前拒绝不支持的格式。

活动根 Codex 任务和显式启用的 Claude 根轮次在 Session 持久化屏障后，可从配对的原生条目开始与结算事件学习具体步骤。采集器保留配置连接、原始原生 Session 与条目标识、有序来源事件引用及报告结果。Codex 保留实际轮次；Claude 保留明确客户端发送 UUID，以及实际助手来源、工具使用和结果消息 UUID，不虚构原生轮次。学习证据丢弃原始参数与输出。明确来自代理、在项目根目录下安全来源路径的简单读取，以及白名单中规范化的检查命令，可以成为可复用步骤。配对且报告完成的 Codex 文件变化元信息，也可保留数量受限的新增、删除和更新操作、安全项目路径，以及更新操作的可选移动目标；原始差异正文会丢弃。这些修改步骤要求按当前任务及当前文件审阅，并独立检查结果；它们不授予权限，也不会重放历史修改。解析器也识别固定的 `/bin/zsh`、`/bin/bash` 或 `/bin/sh` 包装，要求 `-lc` 或 `-c` 加上一个普通单引号包围的白名单命令体；其他 shell、展开、嵌套引号与复合命令不受支持。生成过程至少需要两个不同的具体事实；只有未知工具、结算不匹配、超出上限、中断或继承的工作不能自动生成步骤。原生 `SKILL.md` 命令动作路径仍只是读取观察，完整加载、版本和应用覆盖率均未知。

受支持的原始会话顺序继续操作以可取消、由维护活动持有的新 Y 任务执行，与普通 AgentLoop 轮次及导入历史分开。每次准入获得新的任务标识，并在调度前持久记录原始提供方、配置档案和会话，然后在条目采集前持久记录实际当前原生轮次。普通 Y 后续消息等待该任务结算；取消及服务释放会终止并等待已准入的工作。桥接器只配对当前轮次经过净化的原生开始与结算事件，拒绝重复或冲突标识，并在已有项目学习策略行动前刷新任务及动作记录。之前完成的 Y 轮次、镜像文本和释放回执不会授予新的学习证据。仅用于日志的任务结算独立于原生完成，明确指出步骤证据不受支持或不足。`sequentialLearningMaxItems` 与 `sequentialLearningMaxTaskBytes` 限制条目采集及净化后的提示。学习输入上限分别限制累计完整 Session 事件记录（预留结算空间）与完整证据（含来源身份和事件引用），并在各自写入前检查。证据超限时保留原生完成结果，并标记学习不可用。已有操作上限限制持久化等待。

顺序 Codex 项目文件观察向已有确定性生成器及验证器提供受支持的安全读取或修改事实；检查及命令元信息不会创建 shell 权限。固定版本的公共文件变化协议提供路径、变化类型及报告的完成状态；只有准确当前轮次中配对的通知才能贡献修改事实。此连接并不证明已安装的项目文件子集在关闭 shell 工具后会暴露具体读取通知。不安全、不受支持或只有未知元信息的条目保留明确的证据不足结果。Claude 只进行对话的顺序路由没有配对项目动作步骤，因此记录不受支持结果，不虚构技能学习。夹具通知验证任务所有权及证据处理，而非原生能力可用性或技能使用成功。

确定性的 `native-observation` 生成器会先更新具有相同具体事实集合的受管理项目技能，再考虑创建新路径。不同事实集合属于不同系列；不推断语义相似性或更广泛的去重。自动创建要求启用的项目策略明确指定此生成器、`native-observation-validator` 和创建权限。独立验证器从不可变事实重新计算整个允许的添加内容。只有新技能会获得管理权与策略同意；现有用户、固定、供应商、原生及手工编辑的来源保持受保护。重复的相同步骤不产生草稿。Claude 根路由在同一个活动 Harness Session 的普通轮次间保留受隔离 SDK query，并持久记录独立的公共协议事件；只有配对的净化条目贡献根学习。受支持的一次性子进程流仍只发出单独标明来源的工具观察，不能验证父任务或授权根学习。

持久化提案保留完整来源及保留技能的正文、哈希、资源指纹、权限规则行、字面代码、引用和不确定性。审阅后应用会在来源写入队列内复查这些内容，并保留回滚历史。归档要求活动的保留技能至少覆盖原有范围、拥有等价指令及资源，且所有已注册项目中均不存在入站引用。只要发现提供引用的生成资源或逻辑引用元数据不完整，语义归档就会拒绝，并且不打开这些来源的正文。明确选择接管会记录经过验证的链接元数据，但不会取消此限制；显式归档仍保留完整资源包供人工恢复。归档比较已解析的引用目标：技能引用保留相同的技能身份，匹配的包内资源可以随保留技能迁移，外部文件或 URL 引用保留原目标。不确定的等价性需要独立的明确范围检查。中断应用会在重试前核对已提交的来源变化；拒绝提案会保留历史。

内置 `instruction-redundancy` 执行器移除明确 `References` 标题下同一完整列表中完全重复、独立成行的 Markdown 链接项，包括被空行分隔的重复项。它保留首次引用顺序、空行、非引用字节及正文末尾换行的约定。列表的每个非空行都必须是独立链接项；说明文字、任务、编号或嵌套项以及围栏代码会阻止整个列表的化简。新标题结束列表，不跨标题合并引用。包含缩进或 HTML 的正文保持原样。独立验证器重新计算准确的转换，并将回执绑定到完整提案。重复技能归档要求经过该化简后正文相同、资源完全一致、解析后的引用相容，且保留技能处于活动状态并满足上述范围与调用检查。这些是有限的机械不变量，不保证完整语义等价。

自动维护需要批准 `instruction-redundancy-validator` 策略，并按文件明确启用与当前接管哈希匹配的同意。轮询消费者执行有预算限制的维护；`cleanupSemantic` 立即执行一次。每个文件的检查时间轮换常规选择；保留的候选游标让有界重复技能检查在重启后继续轮换。强制清理跳过常规间隔，仍保留所有权、固定、策略与哈希检查。一般验证器声明只用于审阅，不能授权自动改写。撤销策略会移除自动权限但保留历史；归档会禁用来源同意，使恢复结果持续可见。

将 `native-observation` 与 `native-observation-validator` 绑定的明确项目策略，可以授权创建和更新观察到的流程。Host 在创建前选定准确的已有流程，独立重新计算允许的文本，并仅为新创建的 Y 管理来源启用同意。项目批准不会接管已有文件。没有策略时保留审阅；重复流程不写入。正文、项目增长、操作数量与时间预算在自动来源写入准入前检查。提供方期限会终止其信号并拒绝迟到结果；底层任务完成前会拒绝新的提供方调用；已准入的来源检查、文件操作与提供方任务会在释放时完成，因为文件写入无法强制取消。机械维护不调用模型。

<a id="decision-advice"></a>
## Decision 建议

`decisionStatus`、`decisionCapabilities` 和检查修订版本的 `configureDecision` 负责单独的模型选择，初始关闭。只有明确声明 `auxiliaryGeneration: 'api'` 的精确注册适配器才能准备或执行建议。原生路由（包括缓存的 Codex gpt-6-luna）保持不可用；空的 Harness 工具 schema 或最终响应 schema 无法关闭原生工具。不改变凭据、OAuth 授权、聊天路由或模型偏好。未来的 Hermes JEV 集成需要专用的类型化适配器，不能成为通用自动路由器。

明确的 `retrieve` 请求先进行确定性的项目及共享范围过滤与排序。启用的建议只接收这些已选入的元信息及查询，可以改变顺序，但候选成员和明确选择仍由确定性规则负责。拒绝、无效 JSON 或身份、重复身份、工具块、缺少强度或档位、路由变化、取消、超时或持久化失败会保留确定性顺序。建议不能授予验证、工具、权限、写入所有权或维护权限。列表和图谱浏览不调用模型。

`decision` 部署配置限制完整输入封装字节、保守输入 token 预留、输出字节及 token 和块数、超时、并发调用和日志保留。每次检索最多调用一次，不重试。UTF-8 输入每字节预留一个 token，并在精确模型上下文中单独预留输出。`skill_decision` 在调用及发布建议之前保存独立设置和有上限的完整请求与结果记录。只发送元信息，不发送指令正文、工具输出或会话记录。提供方必须响应取消；释放时等待进行中的操作结束。

`tests/fixtures/decision-labels.json` 的人工标签覆盖相关性、拒绝、明确请求和负向对照。脚本化测试只能证明准入、解析、记录和回退，不能证明实时模型质量。授权的提供方评估需要单独报告召回率、错误选择、拒绝与回退、延迟、token 及提供方披露的费用。

新的 Host 控制器会将上个进程保留为 pending 的建议请求持久结算为 abstained，并记录 `interrupted-before-settlement`。旧选择 ID 和输出被丢弃，不重放请求。新的建议和状态读取等待此准确修复持久完成；修复失败时控制器保持不可用，释放会等待已准入写入。当前控制器的待处理工作不会被误判为中断。

<a id="configuration-and-provider-extension"></a>
## 配置与提供方扩展

原生读取方通过无依赖的[值工具库](../../util/values/README.zh.md)共用项目路径词法检查。学习验证器独立检查保留的事实。

`dshHome`、`agentsHome`、`customSkillDirs` 和 `bundledSkillDir` 选择与文件系统提供方相同的根目录。附加根目录配置必须与挂载的调用来源一致。`bodyBudgetBytes`、`retrievalLimit`、`proposalLimit` 和 `automaticMaintenanceIntervalMs` 限制维护与元数据选择范围。原生提供方使用 `registerNativeProvider()`。学习使用 `registerLearningGenerator()`；`registerLearningValidator()` 注册独立检查。每种注册均返回释放函数。`learningMaxInputBytes`、`learningMaxSources`、`learningMaxEvidence`、`learningMaxResourceFiles` 和 `learningMaxResourceBytes` 限制完整提供方输入、提案和资源检查。资源哈希使用实际字节的有界读取与目录条目的有界检查，并拒绝检查时变化的文件。`maintenanceMaxOperations` 限制一次维护的自动变化数量；`learningOperationTimeoutMs` 设置写入准入期限；`automaticProjectSkillLimit` 限制原生创建造成的项目管理技能增长。

## 理解实现

技能文件及其资源包是内容来源。`skillLibrary` Remote 命名空间提供有范围的清单、按需读取指令、加载记录、显式关联、修订历史和学习提案。`skill_library` 存储域保存管理标记、历史位置及与根哈希绑定的逻辑引用缓存；`skill_learning` 保存证据、完整提案和已批准及已撤销的语义策略记录。

## 模型体验

### 管理与渐进检索

#### 模型看到的内容

管理 API 不会将技能清单或图谱注入模型上下文。`retrieve` 在调用方逐个读取正文前，根据当前项目与共享元数据排序；没有加载适配器的原生条目不参与。面向人的图谱关联来自显式元数据及代码示例之外的 Markdown 资源链接。学习生成器接收独立、有预算限制的请求，其中包含观察记录及选定的完整来源；生成器不能签发验证证据。

#### Token 影响

清单与图谱导航不增加模型 Token。通过现有调用路径加载选定正文沿用该路径的 Token 成本。提案生成会增加有配置预算限制的辅助请求；经审阅缩短的正文可能减少之后的加载大小，但不保证 Token 节省或任务成功。

#### KV Cache 影响

管理读取不改变模型请求前缀。后续上下文变化由现有技能调用负责。辅助提案请求不改写活动任务的请求前缀。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 通用动作删除、任意改写、段落合并、代码变化与不确定的替代关系仍保留为审阅建议。机械维护及原生流程记录不调用模型，也不代表任务成功。原生指令正文与大小仍需要显式加载适配器。
- 未启用预设的根目录、未发现项目与历史使用记录不在当前覆盖范围内。内置生成器要求选定证据具有保留的捕获路由，包括强度或层级是否未设置；路由捕获缺失或控制项冲突时，提案不可用。项目最新路由不能替代缺失的证据路由。关联不代表推断出的相似性或所有权。
- 只要已发现的技能包含生成主题资源，语义归档就不可用。仅凭根文件元数据无法确认子文件的入站引用；显式归档仍可用于有意的恢复操作。
- 归档与修订副本不自动过期；中断恢复可能需要人工检查。哈希检查会串行化技能库操作并拒绝已变动的预览，但不能对任意外部写入者提供操作系统级比较交换锁。
