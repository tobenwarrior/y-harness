# @deepseek-ai/dsh-client-ui-settings-coding-sessions

[English](README.md) | 中文

## 概述

浏览已配置的原生编程会话来源，导入记录，并在设置中选择可读镜像。刷新引入新的来源记录，冲突则保留现有镜像。页面显示原始来源 ID 和连接就绪状态。经审阅的关联导入将引用记录加入冷的普通 Y Session。显式顺序续写及重启恢复遵循 Host 发布的能力及可见所有权状态。

<a id="use-this-package"></a>
## 使用此包

与设置、语言及 Remote 客户端服务一同挂载，并提供 Host [coding-session 服务](../../session/coding-session/README.zh.md)。浏览器入口注入 `slots`、`locale` 及生成的 `remote.codingSessions`；Host 入口不提供权限或配置。

### 来源操作

编程会话区域列出明确配置的原生来源的就绪状态及已导入元数据。原始 profile 来源插件可独立于模型启用注册所选 Codex home 或 Claude profile/项目；已连接的 Codex 后端及已注册的本地 Claude 项目仍是可用来源。浏览分页读取原生元数据；导入选择保留原始 ID 的可读镜像。选择保留镜像时显式请求其记录。刷新失败时保留可见数据，并显示来源分歧。来源断开与不受支持的原生写入交接具有不同的可见状态。

关联导入须选择与所记录项目完全一致的既有冷普通 Y 目标，或明确创建一个。目标审阅显示其规范事件数和摘要、镜像版本，以及已有的关联版本。导入及关联刷新要求使用该准确审阅结果。导入记录标注为引用上下文，不授予当前指令、工具、审批、沙箱、模型或原生写入权。只追加的补偿从未来普通 Y 记录中撤回所属导入上下文，保留原始 Session 日志、原生记录及目标中无关的轮次；它不能撤销已生成的响应。未解决的已准备关联写入必须明确恢复或放弃。仅在 Host 确认本次所属上下文内容均未写入时才允许放弃。

受支持的续写发送人工文本及用户审阅的准确镜像版本。顺序认领还须选择同一项目中实时且空闲的 Y 根 Session，并确认其他原生写入方已关闭，且所选原生配置在释放前保持不变。页面显示提供方工具模式、Y 所有权、显式释放及不确定阻塞状态。续写要求 Y 持有所有权；重新打开原生 CLI 前须完成释放。

重启恢复可用时，须审阅准确的先前接管者、当前镜像版本、中断阶段、已接收轮次、原生回执 ID 及未解决轮次数。恢复要求确认外部写入程序已关闭、原生配置保持不变，并接受所有没有原生回执的已接收轮次。冷读取记录检查允许另行认领，但不能确认先前进程已退出、流已排空或原生记录已持久化。页面在恢复记录中保留这些未知观测，即使后续接管者已释放也不会消除。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节——点击展开</summary>

此功能拥有 `coding-sessions` 设置区域、带类型的中英文文案、控制器派生的组件属性及 `shell.overlay` 中的操作通知。它不从其他客户端插件导入运行时值。重连使旧响应失效并刷新可用状态；所属 fiber 销毁时移除注册、语言席位和回调，并阻止迟到状态更新。插槽重新声明会恢复设置及覆盖层贡献。

Host 负责来源身份、限额、持久协调及续写准入。UI 不授予原生写入、审批、沙箱或模型权限。成功操作更新所选镜像、关联及列表；失败操作保留可读记录并显示临时通知。取消会等待 Host 已接收的写入完成，再读取最终镜像和关联状态。它清除目标审阅，不重放或撤销任何写入；协调失败仍会显示，须稍后重新加载。重新加载来源会更新所选镜像的操作能力，不重新读取其正文，并清除来源不可用的发现页面。版本改变时清除选择，让用户在续写前重新选择并审阅当前记录。

</details>

<a id="model-experience"></a>
## 模型体验

### 编程会话操作

#### 模型看到什么

UI 使用 `remote.codingSessions` 显示来源元数据及可读镜像。浏览及镜像读取不向模型上下文提供提示词、工具 schema 或消息。经审阅的关联导入将历史引用上下文加入目标后续的普通 Y 请求；补偿从未来有效记录中撤回其所属导入上下文。这些操作不授予原生模型或写入权。只有 Host 发布已启用的提供方能力时，显式续写才转发人工文本及用户审阅的镜像版本。顺序认领选择既有 Y 执行权限；它不创建 Agent 或模型轮次。

#### Token 影响

浏览、镜像导入、选择、刷新、目标审阅、关联导入及补偿均不调用模型。关联导入和补偿会改变后续普通 Y 请求的有效记录，因此可能影响其 token 用量。任何受支持原生续写的 token 使用属于 Host 的来源提供方；此 UI 不组装模型请求。

#### KV Cache 影响

显示或刷新镜像不会改变模型请求前缀。关联导入向后续普通 Y 记录追加引用上下文；补偿撤回先前所属的上下文，可能使前缀无法复用。两者均不转移原生缓存状态。原生续写上下文及缓存复用属于来源提供方；显示或刷新镜像不会重建该上下文。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

此界面遵循当前 Host 来源发布的能力。

- 顺序交接要求显式 Host 及来源配置，以及适合的实时 Y 根 Session；仅有读取方时仍只读。
- 无关外部进程仍可重新打开同一原生会话。重启恢复须经明确审阅及冷读取来源检查后才允许另行认领；页面不能从记录推断先前进程已关闭、流已排空或原生记录已持久化。
- 导入保留有界公开记录；私有上下文及未公开的原生细节为 Unknown。原生非文本记录显示为来源标记，不生成可运行的 Harness 工具事件。导入记录不能证明历史技能使用，也不构成学习证据。
