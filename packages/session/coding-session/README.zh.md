# @deepseek-ai/dsh-coding-session

[English](README.md) | 中文

## 概述

浏览已配置的原生编程会话，导入可读记录，并将同一来源刷新到持久 Y 镜像。提供方、授权配置及原生 ID 区分各个来源。本包用于编程会话记录，不处理面向消费者的 ChatGPT 对话。所选原始配置来源可显式启用顺序续写；原生强制排他续写仍是单独的能力。

## 使用此包

与已配置的 storage-domain 和 Typert registry 服务一同挂载。设置消费者是 [ui-settings-coding-sessions](../../client/ui-settings-coding-sessions/README.zh.md)。Codex 发现使用已连接的配置后端；Claude 发现仅使用已注册的工作区目录及实际 SDK 配置根目录。原生发现不会启动模型或要求登录。

Codex 来源身份遵循后端的 `DSH_CODEX_HOME`，该目录作为原生 `CODEX_HOME` 传递；它不会发现另一个普通 CLI 主目录。Claude 来源身份包含 `CLAUDE_CONFIG_DIR` 或 SDK 默认主目录，以及一个已注册项目目录；工作树发现已禁用。配置范围之外的来源需要单独授权的提供方。服务不会为寻找来源而更改配置根目录或身份验证。

### 配置

`pageSize` 限制原生分页大小；`maxEvents` 和 `maxBytes` 限制完整记录和响应，包括记录包装字段。`maxMirrors` 限制保留记录数量，默认值为 500。`maxImportGenerations` 默认为 64，并保留完整回滚代际；`maxEvents` 与 `maxBytes` 也限制完整规范 Y 目标日志及关联日志。`timeoutMs` 限制准入生命周期；取消会排空底层工作。`enableClaudeDiscovery` 默认为 true，可用于关闭本地 Claude 来源注册。`enableSequentialHandoff` 默认为 false。`sequentialTurnTimeoutMs` 单独限制顺序轮次，默认为 600000。还须提供顺序来源适配器，并选择同一项目中实时且空闲的 Y 根 Session；仅挂载读取方不授予模型权限。

将 `@deepseek-ai/dsh-coding-session/claude-source` 与本服务及受管子进程提供方一同挂载，即可选择原始外部 Claude 配置，无需启用模型。其 `sources` 默认为空数组。每个来源须提供稳定的 `id`、可见的 `label`、绝对路径 `profileRoot`、项目 `directory`、`shellHome`、`nodePath`、规范路径 `sdkModulePath` 与 `sdkManifestPath`、可信的 `sdkModuleSha256`、`sdkVersion: '0.3.263'` 及正数 `processGraceMs`。来源身份对所选配置根目录、项目及 id 求摘要。插件不会猜测个人根目录，也不会复制身份验证或记录。

Claude 顺序写入方注册要求 `sequentialHandoff.knownUnmanagedStartup: true`；省略或 false 时来源保持只读。该字段默认为 false，由可信部署配置声明所选账户、配置及机器不存在受管、远程、helper 或父进程启动策略。Codex 注册同样要求两个默认 false 的来源字段 `enableSequentialProjectFiles` 与 `knownNoManagedFeatureOverrides` 均为 true；后者声明原生特性要求不存在或全部为 false，且持续保持不变。这些声明独立于用户关于其他写入方已关闭及配置保持不变的确认。

仍须进行新的原生观察。每次 Claude 发送前，所选配置的 worker 调用公开 `resolveSettings({ cwd, settingSources: [] })`，仅在结果受支持且为空时返回指纹及 `noManagedSettingsObserved: true`。生效设置、来源归属或来源列表非空、形状未知、解析抛错、stderr 出现任何字节或缺少完整 stderr 覆盖证据时，在持久发送标记及查询前拒绝。SDK 0.3.263 不提供解析错误列表、跳过 policy helper 执行，也无法证明新的远程策略不存在。Codex 在初始化后观察 `configRequirements/read`，发现强制 true 特性要求时在任何线程操作前拒绝；该观察不能证明此前未发生 Plugin 预热启动。可信声明属于操作假设，不是策略证书，也不绕过受管策略。提供方细节见 [Claude 适配器](../../subagent/subagent-claude-code/README.zh.md)及 [Codex 适配器](../../llm/llm-pi-ai/README.zh.md)。

显式发现和记录操作启动私有 Node worker，仅在子进程设置 `CLAUDE_CONFIG_DIR` 与 `HOME`；父进程环境保持不变。worker 在导入前验证官方 SDK 清单名称、版本及入口路径，以及配置的模块摘要。记录请求仅接受 `listSessions`、`getSessionInfo` 与 `getSessionMessages`；独立的顺序策略观察使用 `resolveSettings`。完整 UTF8 请求和响应包装字段及原始记录分页受配置的字节限制约束。SDK 与进程失败仅暴露经过清理的错误。注册和 `getState` 不启动 worker；取消及移除会等待子进程完成、输出排空及受管范围释放。

### 记录与恢复

`getState` 返回有界的来源就绪状态及镜像元数据，不包含会话正文。显式选择通过 `detail` 加载正文。导入和刷新保留稳定的原始事件 ID、摘要、顺序及游标；重复读取不会复制记录。原生记录被编辑、截断、重排或存在冲突时，保留原内容并明确标记冲突。只有来源再次扩展保留的前缀，刷新才清除冲突。来源被移除或断开后，保留镜像仍可阅读。

Codex 读取使用已连接桌面后端的 0.160.0 app-server API，与包内的子代理二进制不同。发现发送带 `useStateDbOnly: true` 的 `thread/list`，并使用原生默认的交互式来源过滤。读取先获取元数据，再加载完整 legacy 记录，或通过有界的 `thread/turns/list` 与 `thread/items/list` 分页读取 paginated 记录。两次完整读取必须一致。分页读取不发送完整记录的 `thread/read`，因为其已加载线程路径可能持久化原生状态。支持的读取 API 可能初始化或迁移自身数据库；导入不发送原生轮次或会话写入请求。

Claude 使用已安装的 `@anthropic-ai/claude-agent-sdk` 0.3.263 公开 API：`listSessions`、`getSessionInfo` 及分页 `getSessionMessages`。读取局限于所选项目，保留消息 UUID、包含系统标记，并比较两次完整的元数据和记录读取。每次读取在分页后重新检查原始会话元数据；来源被移除或改变时拒绝导入。原生写入状态保持未知。SDK 根目录变更或已注册工作区被移除会使来源失去就绪状态。非文本记录显示原生标记并保留负载摘要；导入记录不能证明历史技能使用情况。

### 导入到普通 Y 会话

明确审阅过的公开原生历史镜像可以关联到同一已记录项目中的一个选定冷 Y 会话。Host 取得既有 SessionPersistence 写入所有权，并拒绝已发布或仍然在线的目标。关联记录保留提供方、已配置档案、原始原生会话 ID、镜像修订号、原生事件 ID 和摘要，以及每个事件的目标序号和引用文本偏移量。在 Host 所有的日志内，一个活动来源只能关联一个目标，一个活动目标也只能关联一个来源。

每个导入代次将原生用户、助手、系统和工具记录放入一个带有明确标签的引用用户上下文消息。持久化来源为 `coding-session-import`；历史工具只属于观察记录，不授予可执行工具、审批或指令权限。私有上下文和未公开原生细节标为 Unknown。普通 Y 续接使用自己的提供方、策略和工具；导入文本不构成学习证据。

日志准入会重建完整的来源、项目、权限说明及按原生顺序排列的公开记录，并验证每个连续 UTF-16 文本映射。镜像元数据刷新后，各导入代次仍保留原先显示的标题。

目标 surface 为空时，在准入引用历史之前，同一预写批次先保留一个空的受保护系统首节点。局部轮次与步骤在派发边界停止，并使用已有的 `blocked` 结束原因；不记录 AgentLoop 请求、模型用量、学习证据或原生执行。可忽略的 `coding-session/import-initialization` 收据将系统消息 ID 绑定到准确来源、镜像及关联。普通 Y 恢复在该保留首节点上提供自己的提示词。已有非空内容却没有受保护首节点的目标会在日志或目标变更之前拒绝。

重复交付不会添加第二份内容。追加刷新只接受保持不变的原生事件前缀，并添加已验证的后缀。被编辑、重排或截断的原生历史会保留先前导入内容并标记冲突。解决冲突需要审阅和回滚；刷新不会静默替换已保留历史。

带版本的 `coding_session_links` 日志绑定目标的准确持久化修订以及完整暂存的 Session 事件，包括消息 ID、时间戳和分离会话构造器的标记。意图先于目标追加持久化；已提交的关联状态只在目标刷新后可见。显式恢复验证完整存储前缀及准确准备批次，只追加缺失的连续后缀，并可完成已持久化的收据而不重复上下文或改动后续用户回合。任何意外前缀或批次变化都会保留并拒绝。

审阅后可以取消尚未执行的意图，以便在目标变化后重试。取消只修改日志，并保留之前已提交的代次。如果任何计划中的导入、补偿或初始化系统消息 ID 已经出现在目标持久化日志中，或归属该意图的初始化收据已经持久化，则拒绝取消；修改时间戳不会让这些写入成为尚未执行。此类写入需要恢复和受保护的回滚。

Host 取消会拒绝上一取消代次中尚未获准执行的排队变更，并等待已获准工作结束。已获准写入保留其持久化结果或已准备收据。取消后可以执行新的已审阅请求。

回滚对准确归属且仍然有效的导入节点追加单节点投影替换。它从之后的模型历史中撤下这些节点，保留原始原生收据和只追加 Session 日志，并保留后续 Y 回合。它无法撤销已经利用导入上下文生成的回复。已被替换、压缩或编辑的导入节点会拒绝补偿，避免覆盖当前用户内容。

部署限制包括完整 UTF-8 日志及清单字节数、保留事件数、映射、记录和代次数。达到限制时拒绝操作，不会丢弃回滚收据腾出空间。日志只有一个活动 Host/domain 所有者。SessionPersistence 保护目标写入，但该功能不提供全局原生写入排他，也不阻止任意外部进程写入日志文件。

目标工具轮次未完成时拒绝冷写入，须先通过普通 Y 恢复修复，再审阅新的规范修订号。取消会终止目标准入，等待不可取消的句柄关闭，并刷新设置中的映射列表；它不承诺撤销已提交写入。

## 理解实现

<details>
<summary>实现细节——点击展开</summary>

`coding_sessions` 存储域保存独立镜像记录，与可运行的 Harness Session 日志分离。来源注册属于原生连接；移除注册会改变可用状态，但不会删除记录。操作按照实际底层工作串行执行。读取超时可以提前返回，但取消或销毁会隔离迟到响应，并在关闭存储域前等待原生读取和已准入持久写入完成。已准入写入可在排空期间完成；完整销毁返回后不存在剩余写入。

### 续写所有权

顺序认领要求原始来源、配置及会话、用户审阅的准确版本及项目、选定的实时 Y 根 Session，并明确确认其他原生写入方已关闭，且所选原生配置在释放前保持不变。全新私有进程在启动轮次前读取原始记录；记录过时则拒绝认领。后续轮次再次检查同一实时 Agent 及保留记录，恢复原始原生 ID，并使用提供方公开的工具模式。此模式不能阻止无关进程重新打开来源。

独立的 `coding_session_handoffs` 存储域在原生操作前记录所有权。认领、续写及释放均可见；持久化或进程关闭不确定时阻止更多续写。释放要求所属进程退出、流排空，并以新的冷读取确认保留前缀及已完成原生轮次。这些观察证明轮次已保存，不构成通用原生记录器或上下文证书。Host 重启后，未解决标记保留旧所有权阶段并保持阻塞，因为元数据不能重建原进程句柄。操作员审阅当前镜像修订号及旧所有者令牌、停止先前写入方并确认原生配置保持稳定后，`recoverSequential` 通过已连接的读取器检查确切原始来源及保留前缀。没有已记录原生轮次回执的已准入请求需要明确接受。历史分歧保留为冲突；来源恢复保留前缀并重新审阅冲突修订号后，可再次进行冷读取。提交的 `recovered-acknowledged` 检查点允许另一次独立的新认领，同时保留先前准入请求、已观察轮次 ID，以及旧进程退出、流排空和持久化证据的缺失。恢复不报告原所有权已成功释放，后续所有者的释放也不会解决先前未知的观察。每次新认领仍需启用写入方及启动选项；冷恢复本身不启动轮次。

显式注册的排他写入方必须先原子排除所有原生或外部写入方，再返回空闲租约。Host 在持有所有权期间检查原始提供方、配置及原生 ID、用户审阅的版本、游标和摘要。它对该身份调用 `resumeOriginal`，导入已结束的来源结果，并等待释放。提供方负责正常的来源绑定审批和沙箱策略，并必须在释放前结束被取消的资源。Y 本地租约、空闲观察、复制记录或替换来源都不能承担此角色。

</details>

<a id="model-experience"></a>
## 模型体验

### 原生记录与续写准入

#### 模型看到什么

原生发现、镜像导入及刷新不注册模型可见的提示词、工具或输入。显式普通 Y 关联导入会让目标后续请求看到带来源标记的历史引用上下文；它不提供当前指令、工具权限或学习证据。`coding_sessions` 记录是可读镜像，与可运行的 Harness Session 日志分离。显式启用的顺序续写将人工文本传给原始原生提供方、配置及会话。原生提供方保留自身上下文；镜像不是替换会话记录。Claude 对话模式禁用项目工具。Codex 的 project-files 模式将文件更改限制在所选 Y 根代理的可写策略内；shell、JS、多代理、原生扩展、提权及额外权限授予不可用。更强的排他写入方使用单独的来源租约。

#### Token 影响

发现、导入和刷新不调用模型，也不消耗模型 token。受支持写入方的续写可能消耗原生模型 token；已注册来源提供方负责其请求和保留的上下文，而不是从镜像重建模型输入。

#### KV Cache 影响

读取操作不追加或替换模型请求前缀。原生续写上下文及缓存行为属于已注册写入提供方；镜像本身不建立缓存复用，也不迁移实时运行状态。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

顺序续写是显式操作交接。用户须先关闭其他写入方；原生 CLI 以同一 ID 恢复前，Y 须完成释放。

- 已交付原生读取方仍不提供原生强制排他续写；顺序所有权不实现该更强能力。
- Claude 顺序模式不执行项目工具；Codex 仅支持其声明的 project-files 子集。保留原生上下文仍受提供方压缩及保留策略约束。
- Host 重启后，未解决所有权不能仅凭记录元数据释放。代码回滚不能撤销已追加的原生轮次。
- 顺序轮次在普通 AgentLoop 任务外使用所选 Y 根代理权限，不生成普通 Y 任务的技能学习证据。Codex 配置检查仅是观察；不存在能排除任意外部编辑的原子配置固定。
- 可信启动声明不能证明全局策略不存在；不受支持或未作声明的部署保持只读。
- 原生读取属于观察快照；两次一致的完整读取不构成原生写入排他权。
- 进程内 SDK 读取不能物理取消；安全销毁须等待其完成。显式来源 worker 可以被终止，销毁完成前必须确认受管范围已完全停稳。
- 达到保留容量时拒绝更多导入，不删除记录；部署可提高配置上限。

<a id="dev-note"></a>

受支持的上游 API 无法重新附加或自然释放丢失的所有权句柄。操作员确认的重启检查点保留这种不确定性，也不排除任意外部写入方。

第 2 版 `coding_session_handoffs` 日志拒绝前版读取器及已有的第 1 版存储单元，且不进行自动迁移。部署前，已有第 1 版数据需要经过明确审阅的离线转换，保留每个标记及其备份；产生后续准入请求后恢复旧备份会丢失不确定状态，不属于受支持的回滚。本地功能阶段不转换任何用户日志。
