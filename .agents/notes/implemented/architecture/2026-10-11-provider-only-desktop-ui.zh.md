# Agent Note: 仅提供方范围的 Desktop 账号界面

Status: implemented

[English](2026-10-11-provider-only-desktop-ui.md) | 中文

## 问题

侧边栏中的提供方资料与账号设置分类会把远程推理凭据呈现为应用身份。即使启动无需账号，已保存的欢迎步骤也可能重新带出这一身份。

## 决策

Desktop 账号插件仅通过 `settings.models.footer` 提供可选的 DeepSeek 连接控件。中性设置入口与产品分类不依赖提供方状态。模型目录加载中或失败时仍渲染页脚，因此连接提供方不必先完成已认证的模型发现。

连接、取消、经确认的断开、资料、用量、余额和赠金通知均位于模型设置的提供方范围内。离开该范围不会断开连接或确认尚未显示的通知。既有 Host 授权存储、PKCE、回调校验、明确撤销及推理检查保留各自职责。API Key 路由与其它提供方保留现有控件。

当前组合不再注册产品账号菜单、账号分类、API Key 编辑器前的账号选择、账号额度接管或已保存介绍覆盖层。既有组件、设置 schema、进度和偏好保持不变；仅停止这些展示，不迁移凭据或用户资料。

本决策部分取代[可选 Desktop 账号访问](2026-10-11-optional-desktop-account.zh.md)及[账号登录](2026-09-14-deepseek-account-login.zh.md)中的展示与已保存介绍流程显示条件。其启动、默认模型保留、协议和凭据规则仍有效。上游包名、提供方标签及许可声明保留。

## 考虑过的替代方案

**仅在未登录时隐藏资料。** 现有授权在后续启动中仍会变成产品身份。

**仅向已认证模型行附加连接控件。** 未连接时模型目录为空且该行隐藏，无法提供可发现的连接入口。

**清空授权或完成旧欢迎进度。** 移动展示不包含这两种操作的授权，且都会静默更改用户状态。

## 后果

首次及现有资料均采用无需账号的启动和独立于提供方的应用身份。内置 DeepSeek 服务仍需有效授权或 API Key 以及适用额度；界面不提供匿名推理权限。提供方错误仍按任务错误展示，计费操作位于模型设置。聚焦组件与注册测试覆盖此职责划分；最终集成仍需原生构建验收。
