# Agent Note: 可选的 Desktop 账号访问

Status: implemented

[English](2026-10-11-optional-desktop-account.md) | 中文

## 问题

优先要求凭据的启动流程会在用户选择模型提供方前阻止访问本地项目和文件。账号登录成功还曾覆盖已保存的默认模型，而 API Key 发现会在用户未明确选择时应用介绍流程偏好。

## 决策

Desktop 在 Host 就绪和语言解析完成后打开工作区，不以账号状态或提供方凭据限制进入。退出登录、账号失效和传输失败时保留该文档。[账号登录](2026-09-14-deepseek-account-login.zh.md)提供方继续负责可选 PKCE、凭据持久化、取消及推理认证。本决策部分取代[原生欢迎窗口记录](2026-09-08-desktop-welcome-window-material.zh.md)中的启动策略；保留的渲染器、原生材质和受限 preload 仍是独立组件。

介绍流程进度保持不可见，包括已保存的额度、用途和过程步骤。启动不会写入完成标记或默认偏好。存储值保留现有 schema 且不修改。[仅提供方界面决策](2026-10-11-provider-only-desktop-ui.zh.md)部分取代此前已保存步骤的显示策略。

可选登录仅在不存在提供方 API Key 引用和已保存模型覆盖项时初始化账号模型。初始化在异步发现后重新读取脱敏设置，并按已观察到的修订号写入，以保留并发模型选择。现有会话保留各自的模型选择。

无需账号即可访问应用不代表获得推理权限。内置 DeepSeek 路由通过 Platform 账号授权或独立配置的 API Key 调用远程官方服务。账号模型需要有效登录和可用账号额度；其他提供方保留各自的认证和计费要求。[官方计费文档](https://api-docs.deepseek.com/quick_start/pricing/)说明按 token 用量从赠金或充值余额扣费。

## 考虑过的替代方案

**为优先凭据的启动流程持久化跳过标记。** 这仍将账号配置作为默认入口，并仅为打开本地功能增加持久化状态。直接打开工作区可移除此依赖，不改变现有 profile。

**存在密钥时自动完成介绍流程。** 凭据元数据不能表达用户对对话视图、用量或开发者工具的偏好。这些选择保持显式。

**每次登录后替换默认模型。** 登录表达对某个提供方的授权，不表示允许替换已保存的模型选择。

## 后果

用户可离线打开本地功能，并在推理需要时选择账号或提供方配置。认证和额度失败仍阻止推理；应用不会隐式提供凭据、账号授权或额度。应用无需迁移即可保留 profile、会话及已存储的介绍进度。未使用的欢迎渲染器继续打包；移除它属于独立清理。

Desktop 启动、账号界面和模型初始化回归覆盖无凭据进入、现有 profile、取消、错误和重复启动。构建后浏览器与已安装应用检查仍是最终视觉和操作系统验收所必需的。
